Level 0 · the whole thing on one page

System diagram: one review, from Booking.com to the manager's screen

Arrows show the direction the data moves. The numbers match the steps underneath. Dashed boxes are the three platforms the system runs on.

What happens, step by step

  1. A run starts: every day from the schedule, or when someone presses Collect now.
  2. The collector opens each hotel's public page in Chromium and reads the reviews the page itself loads, newest first. It stops after 20 reviews in a row that are already stored.
  3. Each record is checked (required fields, score between 0 and 10, valid dates) and saved. The same review can never be stored twice. One run-log row is written per hotel.
  4. The classifier reads reviews that have no topic tags yet and writes the tags.
  5. When a page is opened, the web app reads the reviews, tags and run log on the server.
  6. The server works out every figure and sends finished pages to the browser.
  7. Collect now calls the web app, which asks GitHub to start step 1. The button then checks progress every 3 seconds.

What happens when something fails

  • The browser cannot read a hotel: that hotel alone falls back to SearchApi for its newest 30 reviews. Other hotels carry on.
  • More than 20% of a hotel's records fail the checks: nothing is saved for that hotel, because the page has probably changed.
  • The source says it has reviews but returns none: treated as a broken parser, not as "no reviews".
  • Any failure: nothing already stored is deleted, the failure is written to the run log, and the dashboard shows a red dot instead of a green one.
  • Classification still runs after a failed collection, so reviews that did arrive get their topics.
